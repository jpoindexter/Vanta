Vanta Desktop · Flow report · 29 July 2026

Queue the next task. Steer the current one.

This report defines the complete follow-up flow for Vanta’s desktop composer while preserving Codex’s proven runtime distinction and Vanta’s Black, Bone, and Signal Violet identity.

Scope: composer commands, queued-message management, interruption, retry, and recovery.

Interaction rule

Queue next starts a new task after the current one. Steer now adds the message to the current task without interrupting it.

Flow: Choose the follow-up action

Pattern source: flow-ai-chat · Entry point: composer while Vanta is working

  1. 1See the active task

    The composer stays enabled. Progress names the current plan step and the Stop control occupies the send position.

    Primary action: Write a follow-up → composer draft

  2. 2Choose Queue next or Steer now

    The visible follow-up control states the current default. The footer shows both keyboard paths.

    Primary action: Queue next → add a FIFO follow-up

    Choose Steer now → add the message to the active task immediately.
  3. 3Confirm the result

    Queued messages appear above the composer with their order. Steered messages appear in the current conversation.

    Primary action: Continue working → active task

Flow: Manage queued messages

Pattern source: flow-ai-chat + accessibility · Entry point: Queue panel

  1. 1Review the queue

    The panel shows the count, order, and plain-language behavior: “Runs after the current task.”

    Primary action: Steer now → move one message into the active task

  2. 2Edit or reorder

    Drag changes order. Move earlier and Move later provide the required non-drag alternative. Edit restores the message to the composer.

    Primary action: Edit message → composer draft

  3. 3Remove with recovery

    Remove acts immediately and offers Undo for 6 seconds. No generic confirmation interrupts routine queue cleanup.

    Primary action: Undo → restore the same queue position

Flow: Stop and recover

Pattern source: flow-errors · Entry point: Stop during an active task

  1. 1Stop the current task

    Vanta keeps the partial result, draft, attachments, and queued messages.

    Primary action: Stop task → interrupted state

  2. 2Review the paused queue

    A persistent message says: “Queue paused. Your messages are safe.” Nothing runs until the operator resumes it.

    Primary action: Resume queue → start the first queued task

  3. 3Recover a failed message

    The failed row stays in place and says what happened. Retry sends only that message; Edit and Remove remain available.

    Primary action: Retry message → retry only the failed item

    Failure repeats → keep the row and recovery controls visible; do not silently loop.

Anti-pattern audit

CheckVerdictEvidence
Dead composer during generationPassThe composer remains usable and exposes both follow-up paths.
Queue and steer use the same labelPassEvery action uses the approved “Queue next” or “Steer now” term.
Interrupted work disappearsPassThe queue pauses, remains visible, and requires Resume queue.
Drag-only reorderingPassMove earlier and Move later are keyboard and pointer alternatives.
Removal has no recoveryPassRemove from queue offers a 6-second Undo action.
Generic failure copyPassThe row names the failed message and retains Retry, Edit, and Remove.
Prototype implies durable persistenceResolvedThe demo now restores a versioned local queue after reload. Production uses a permission-restricted atomic queue store and has restart-recovery tests.
Automated accessibility scan treated as complete proofResolvedThe production receipt records zero serious axe findings and a packaged macOS VoiceOver, keyboard-only flow with zero pointer events.
