## Startup failure: root cause found (2026-10-14), fix awaiting its "after" run
- **Cause (E: kept runtime log of a failed run under load):** `Error: listen EADDRINUSE: address already in use 127.0.0.1:7790`. The launcher's free-port probe closes its socket before the runtime binds (seconds later with the source runtime), so a second launch took the same port in that gap and the runtime exited with code 1, shown as "Vanta's background service stopped right after starting". The failing step set (a1,b,c,d,g, about 90 s) matches the original failure. It happened while two Electron proofs ran at once; with one app and a quiet machine it did not occur in 40+ runs.
- **Fix (`0b7517ef`):** the launcher flags an `EADDRINUSE` early exit and the app retries up to 3 times on the next port. Executed: a real-runtime test starts the actual runtime with its probed port already held by another process and recovers on the next port; with retries off the same test fails (negative control). 651 `electron/vanta` tests pass.
- **Also fixed:** the runtime's output was never saved and every early-exit error was a bare code; it is now kept in `userData/logs/runtime.log` (timestamped) and its last lines are in the error text. `flake.mjs --keep` now really keeps failed runs' sandboxes (it did not forward the flag). Step `e` waited a fixed 2.5 s after a project switch and read the page once; it now waits up to 60 s and records how long the switch took (earlier `e` failures under load were that sampling race with the slower source runtime, not a crashed runtime).
- **Not yet done:** an "after" run under the same two-app load with the fix in the build; until it is clean the startup path is not called fixed. The packaged app uses a precompiled runtime bundle and starts faster, so the port gap is smaller there.
