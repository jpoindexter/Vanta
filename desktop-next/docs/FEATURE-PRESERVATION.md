**Legend**
- **Paths:** `src/` is `desktop-next/apps/desktop/src/` at 9e13cd53. `el/` is `desktop-next/apps/desktop/electron/`. "HEAD" means the integrated tree.
- **Backend codes:**
  - OK: the Vanta server has the endpoint and the gateway or bridge maps it.
  - ROUTE: the Vanta route exists but nothing maps it yet.
  - PART: partial coverage.
  - NONE: no Vanta equivalent.
  - STUB: the Electron bridge member is typed-unsupported in the Vanta shell.
  - LOCAL: renderer-only.
- **Shorthands:**
  - NONE-P: no profile route. `/api/profiles*` and `profiles.*` RPC are unsupported and the bridge `profile.*` returns null. Vanta's agent-profile concept exists only as library and CLI (`vanta-ts/src/profiles/store.ts`).
  - NONE-B: no bot or roster route. Library-only analogues are `vanta-ts/src/team`, `profiles`, `fleet` and `subagent`.
  - NONE-C: no config route. `/api/config*` and `/api/env` are unsupported.
  - STUB-FS: `readDir`, `gitRoot` and `watchDirectory` are stubbed.
- **Now:**
  - KEPT / CHANGED / REMOVED / HIDDEN: what happened to the control in HEAD.
  - STAGED: the code lives under `app/vanta` but is mounted only by the fixtures harness.
  - INERT: the control is present but its native or backend call rejects.
- **Keys:** `⌘` means mod (Ctrl off macOS). Chords come from `src/lib/keybinds/actions.ts`. Where I cite a chord for an unbound action I say "unbound".

## Findings

1. **What "Bots" are.** Hermes Bot Mode (`plugins/hermes-bots`) is a roster where one bot is one Hermes profile, meaning an isolated agent home with its own config, skills, `SOUL.md` and sessions. Clicking a bot opens its single continuous "Bot Chat". The same plugin adds group chats, user sections, a bot-scoped Routines tile, a per-bot Screen portal, `@bot` mention routing and a bot-to-bot relay. Bots are not messaging channels (Connections) and not subagents (the Agents overlay).
   - **Vanta equivalent.** There is no single one. The nearest are the worker roster `vanta-ts/src/team` (role, model, tools, status, manager edge, hire, org chart), the agent profiles in `vanta-ts/src/profiles/store.ts`, `fleet/` and `subagent/`. None has a desktop HTTP route.
   - **Proposed home.** The "Company" nav row, which `destinations.ts` already reserves (F-069 to F-076).
2. **Bottom-left row** (F-058 to F-068, all in the Hermes profile rail). Home toggles default versus all profiles, and the glyph becomes "layers" when showing all. "+" opens New profile. The cloud-download icon imports a shared profile archive. "…" opens the Manage profiles page. The plug opens Settings > Gateways and appears only while a single connection exists. "CRON JOBS" above it is the cron section (F-054). The "D / Default / Local · Mock Model + gear" chip is Vanta's own `sidebar-footer.tsx`, not Hermes.
3. **Layout editor, HUD, swap sidebars.**
   - Layout editor is the ephemeral `$layoutEditMode`. It shows a floating "Layouts" card that rewrites the pane-shell tree, which is persisted per interface mode. ⌘-click resets the layout.
   - HUD mode is `$hudActive` / `$hudSession` (not persisted). It opens a second frameless, always-on-top Electron window running the full renderer in HUD variant. It is inert in the Vanta shell because every `hud.*` bridge member is stubbed.
   - Swap sidebars is `$panesFlipped` (persisted per mode) and mirrors the tree.
4. **Settings sections.** Model; Chat; Appearance; Workspace; Safety; Browser plus Passwords & Logins; Memory & Context; Voice; Advanced; Notifications; Billing; Providers (Accounts, API keys, Custom Endpoints, Local Models); Gateways; Keyboard Shortcuts (with HUD gesture and Screen capture); Tools & Keys; Archive and Sessions; Plugins; About (updates and uninstall). Each has sub-pages, listed in F-155 to F-180. The wireframe sheet has five sections: General, Models, Permissions, Voice, Appearance.
5. **Palette, window menu, tray.**
   - Palette contents are F-181 to F-189.
   - Menus, tray, quick entry and the other floating windows are F-195 to F-211.
   - The Hermes tray menu is "Show Hermes" and "Quit Hermes".
   - The Vanta Electron entry (`electron/vanta/entry.ts`) sets no application menu, tray, quick entry, HUD, pet or find-in-page. 217 of the 268 `window.hermesDesktop` members are typed-unsupported (`docs/ipc-surface-2026-10-13.md`).
6. **Features that need Hermes-Python backend work with no Vanta equivalent today.** Only 18 gateway RPC methods are mapped (`api/vanta/dispatch.ts`). Everything below is either server work or DROP-NEEDS-OWNER-OK:
   - profiles and bots;
   - named projects (`projects.*`);
   - session search, fork, unread state and export;
   - rewind and checkpoint restore;
   - `/goal`, `/loop`, `/heartbeat` and subagent controls, todos and background processes;
   - context usage, clarify, and vault, sudo and secret prompts;
   - config schema and `/api/env`;
   - skills hub and toggles, toolset toggles, plugin catalog;
   - webhooks, cron writes, memory graph;
   - foreign session import, handoff and pets;
   - ops: usage, doctor, backup and curator.
7. **Cron to Vanta schedules.** Vanta has only `GET /api/schedules`, which returns `CronEntry`: numeric id, `cron`, `instruction`, `status` (active or paused), optional mode, script and authority fields, and `routine`. Hermes `CronJob` has a string id, name, deliver target, model, last and next run times, and last error. A mapper is needed for name, enabled, and last and next run. The library functions `addCron`, `removeCron`, `authorizeCron`, `isDue` and `hasMissedFire` exist in `vanta-ts/src/schedule/cron.ts` but have no route. Needed routes: `POST /api/schedules/{create,update,pause,resume,trigger,delete}`, runs, and blueprints. The sidebar cron section (F-054) becomes the Schedules page. The staged adapter is `app/vanta/adapters/cron-rows.ts`.
8. **Profiles to Vanta.** `/api/runtime/profiles` (`runtime-profile-api.ts`) is a local-model launch contract (backend, model path, endpoint, resources, env, policy scope). Its create, clone, select, import and export actions map only to Settings > Models > Local runtime. They do not map to Hermes profiles.
   - **Hermes profile equivalent.** `vanta-ts/src/profiles/store.ts` provides `createProfile`, `cloneProfile`, `switchProfile`, `archiveProfile`, `updateProfileDefinition`, `setProfileTools`, the inbox, and `distribution.ts` install and update. It is CLI-only (`vanta profile(s)`) and has no HTTP route. There is no SOUL.md editor, colour or default-profile equivalent.
9. **What is actually mounted in HEAD.** Only `VantaSidebar`, `VantaTitlebar`, the composer chips, message actions and the approval card replaced Hermes chrome. The Vanta palette, Settings sheet, Workbench, Home and list pages sit under `app/vanta` and are used only by `app/vanta/fixtures/harness.tsx`. The Hermes palette, Settings overlay and right-side panes still run, and their native backing (`readDir`, `git.*`, `terminal.*`, `hud.*`) is stubbed. Those rows are marked INERT.
10. **Nous and brand residue still in code.** Billing, the free-tier chip, dialog and challenge window, the Nous provider group, the Terms butterbar, Send diagnostics to Nous support, and `/subscription`, `/topup`, `/login` are all present. `en.ts` still has 249 "Hermes" strings. Telemetry is already neutralised (recorders are no-ops, consent components emptied), but its mounts remain.
11. **Reachability proposal.** The titlebar "…" More menu should hold: Settings, Layout editor, Swap sidebars, Show/Hide right sidebar, HUD or mini window, Profile submenu, Show status bar, Simple mode, Keyboard shortcuts, Find, Zoom, New window and Reload window. That keeps each utility at two clicks or fewer with its existing chord.
12. **Unverified.**
    - Whether the BOTS tab is visible at runtime in the Vanta chrome.
    - Line numbers marked as ranges or file-only.
    - Whether the HUD toggle in More throws visibly or fails silently.
