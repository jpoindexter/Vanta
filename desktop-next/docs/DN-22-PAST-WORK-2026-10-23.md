## Demonstrated defect and fix

The real source app could search and save, but reuse navigated to Home and lost
the prompt. The old handler only navigated to the root route; it did not close
the separate Home state or request a fresh-session draft. Its delayed composer
event therefore had no chat composer to receive it.

Before editing that behavior, reuse-run.test.tsx reproduced Home remaining open
(expected false, actual true). Reuse now closes Home, prepares the normal new-chat
profile, sets the sessions workspace scope and requests the existing fresh-draft
lifecycle before inserting text. No backend run, tool call or approval is replayed.
The existing short composer-mount delay is unchanged; slow-mount race testing
was not performed.
