Vanta Desktop wireframe

Structure for the agent dashboard and chat, grayscale on purpose. Click through it: it is the recommended layout, with the alternatives we compared and the open questions below.

WhoOne operator running research, documents, files, schedules and bounded business tasks, who needs to supervise an agent that keeps working while they are elsewhere.
GoalsStart work in one step. See what needs me right now. Approve exactly what will happen. Find outputs. Recover after a stop or restart.
ProblemThe current app hides status, repeats approvals, mixes five styles and treats chat, settings and monitoring as separate worlds.

Three structurally different concepts

Compared against the shell patterns in flow-app-shell and the AI-chat flow rules. Concept A is chat-first with a supervision Home; B and C each lend one idea to it.

A. Sidebar + thread + workbench Recommended base

Wins: matches how work is done (one task at a time), proven by Slack, Linear and Codex-style apps; approvals are inline where the action happened; the thread stays calm.

Costs: supervising many runs needs a second surface, which is Home.

Wins: best for scanning many runs, keyboard j/k, status first.

Costs: three columns squeeze the thread below 480px on laptops; feels like a mail client for a task that is a conversation.

Taken from it: the sidebar session rows carry status shape and time, and Needs you works like a priority filter.

Wins: instant answer to "what is the agent doing", good for the business-operator story.

Costs: a board is a poor place to read or steer one task; users would open every card in a slide-over, which becomes concept A anyway.

Taken from it: Home shows Needs you, Running now, Next up and Recent outputs as the first screen of supervision.

Controlled convergence: still unexplored

  • A compact mini window for the tray that opens the same session.

Open questions (this artifact does not answer them)

  • Launch screen: reopen the last chat (recommended) or land on Home?
  • Workbench default tab: Changes for coding tasks, Outputs for research tasks, or last used?
  • Sessions in the titlebar: drop tabs for good, or allow tabs only when two chats are pinned side by side?
  • Schedules scope: do monitors appear in the session list or only under Schedules?
  • Mini window and tray: opens the same session read-only until focused, or full composer?
  • Approval for shell commands: keep project-wide Always, or move to per-command-prefix grants (owner decision pending)?

Anti-pattern check

wireframe-fundamentals: three concepts compared, fidelity matched to what is decided. wireframe-elements: standard components only, real labels on every button and nav item. wireframe-principles: one primary action per region, three hierarchy levels, state shown by shape and word, never color alone. flow-ai-chat: stop replaces send, tool steps collapsed, scoped approvals, jump to latest not yet drawn (listed below). flow-app-shell: collapse order sidebar to rail to drawer, panels overlay rather than squeeze.

Not drawn yet: jump-to-latest pill, version pager for regenerate, edit-message fork, message search, drag and drop attachments, per-connection setup flows, onboarding.
