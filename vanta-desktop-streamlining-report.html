01 · What survives

Preserve capability. Reduce exposure.

The original user report that the app felt overblown matched the baseline DOM: Files, Activity, Diff, mode, and status recurred across multiple surfaces. The current build applies the target disclosure model.

  • Combine model and mode controls
  • Collapse progress detail by default

  • Duplicate result/status copy
Blocker

Three navigation systems compete

Top-right icons, the task-header context button, and the command palette all expose the inspector.

Observed Files has four DOM entry points; Activity and Diff each have three. One “Review” trigger plus the command palette covers the same need.

Blocker

Prototype shortcuts over-promise

The palette advertises shortcuts that the script does not implement.

Observed ⌘D, ⌘⇧F, and ⌘⇧A appear in UI; only ⌘K and Shift+Tab have listeners.

Important

Status is repeated, not prioritized

“Ready,” “Ready for review,” and the final result note describe the same state in three regions.

Inferred Repetition makes the shell feel busy and weakens the one message that should tell the operator what happens next.

Important

Selected state is mostly visual

Task and inspector selection need semantic state, not only an .active class.

Observed Add aria-current for the task and tab semantics or aria-pressed for inspector views; mark decorative SVGs hidden.

Monitor

Discoverability may fall after hiding controls

Reducing chrome only works if Review and command search remain easy to find.

Inferred Test task-based discovery instead of assuming a cleaner screen is automatically more usable.

03 · Codex transfer

Borrow behavior, not density.

The official repository establishes the turn contract. The installed desktop bundle establishes current queue controls and recovery states; visual styling remains Vanta’s own.

Use in Vanta

  • Adaptive footer: prioritize the active instruction, then collapse passive context by width.
  • Command popup: keep advanced actions searchable instead of permanently visible.
  • Inline approvals: present permission decisions inside the active turn with command or diff context.
  • Separate queue and steer: queue a FIFO follow-up turn or steer the active turn without conflating the two.
  • Recover interruption: pause queued work, preserve unsent input, and require an explicit Resume.
  • Editable queue: support reorder, edit, delete, retry, and a saved queue/steer preference.
  • Ambient title state: use the window title or subtle task row for working/action-required state.
  • Thread primitives: preserve resume, fork, search, saved runs, and long-running tasks.

Do not copy into the default shell

  • Every slash command as persistent navigation
  • TUI-specific key hints at all times
  • Raw output, Vim, and editor controls for every operator
  • Status-line configuration as primary UI
  • Codex branding, spacing, or pixel styling
  • Infrastructure telemetry without an active problem

04 · Product risk

The product bet is sound; usability needs proof.

Assessment follows the four-risk model. This is not a launch verdict because production performance, retention, and business evidence were not part of the artifact.

ValueSupported

The operator explicitly wants a calmer shell while retaining agent power.

UsabilityConditional

Fewer controls helps only if Review, mode, and attachments remain discoverable.

FeasibilityHigh

The existing demo already has the drawer, palette, composer, and responsive shell.

ViabilityUnknown

No pricing, retention, support-cost, or distribution evidence was reviewed.

The first pass removes cognitive load. The second makes disclosure trustworthy. The third proves that simplification did not hide essential work.

06 · Validation

Test the decisions, not the polish.

Use five real operator tasks or seven days of normal use, whichever comes first.

Done criterion

  1. Start a new task and submit the first prompt in under 15 seconds.
  2. Attach one file and one folder without leaving the composer.
  3. Find changed files and open the diff in under 10 seconds.
  4. Change operating mode, then correctly identify the active mode.
  5. Resolve an inline approval and verify the agent resumes once.
  6. Resume a saved run or prior task without losing task context.
  7. Complete every critical path with keyboard-only navigation.

Stop rule

If two of five trials cannot find Review or mode within 10 seconds, do not restore all old chrome. Re-expose only the failed control and retest.

07 · Boundaries

What this report does not claim.

Calibration matters: source inspection can establish structure and coded behavior, not production usage quality.

Evidence boundaries
  • Executed: the target demo source was inspected and its repeated entry points were counted.
  • Executed: browser flows opened every primary destination, navigated history, searched the command palette, switched tasks, opened Review and Diff, dropped one folder as one chip, queued/removed/undid/stopped/resumed work, persisted persona/model/mode/view across reload, and validated the 390 × 844 compact shell without horizontal overflow.
  • Executed: Codex’s public queue, steering, restoration, and turn protocol were traced at commit 88d6c2b; the installed desktop queue component in Codex 26.721.41059 was also inspected.
  • Observed: the desktop component exposes queue/steer switching, sortable messages, edit/delete actions, interrupted-queue recovery, retry states, and per-conversation persistence.
  • Not established: the desktop app’s unminified source or source maps, production Vanta performance, multi-user usability, retention, or business viability.
Non-goals
  • Do not clone Codex’s visual identity.
  • Do not remove providers, MCP, memory, saved runs, or safety approvals.
  • Do not hide irreversible action details.
  • Do not make drag-and-drop the only attachment path.
  • Do not turn this report into a broader desktop rewrite.
