# Vanta vs Hermes vs OpenClaw

Vanta, [Hermes Agent](https://github.com/NousResearch/hermes-agent) (Nous Research), and
[OpenClaw](https://github.com/openclaw/openclaw) are the same category: local, self-hosted
personal agents you run on your own hardware, model-provider-agnostic, reachable from your
own machine or a cheap VPS. They share most of their shape — CLI + TUI, messaging
gateways, skills, cross-session memory, subagents, scheduled jobs, browser and shell
control, MCP, an Electron desktop app.

:::note Honest by design
Because the three are so close, most rows below are **parity** (`≈`) — and we mark them as
parity, not as Vanta advantages. There are exactly three rows where Vanta is genuinely
different, and a few where Hermes or OpenClaw lead today. A comparison table is only worth
anything if you can trust it, so this one is built to survive a skeptic, not to win.
:::

## Where Vanta is genuinely different

Two are Vanta-only; the third is a local-first take on something Hermes also does:

1. **The intended boundary is a separate layer, not model policy.** Vanta's
   [Rust kernel](/kernel) classifies standard-dispatch actions allow / ask /
   block and records audit evidence; sandboxing adds containment. The current
   trust roadmap closes audited hook, plugin, MCP, factory, scheduler, worker,
   credential, and local-API paths before this can be called unavoidable.
2. **Goal-aware gating.** Vanta carries a goal ledger and dependency graph, so it knows
   the goal _before_ it chooses a tool, and an action that doesn't serve the goal is
   visible as such. _(Vanta-only.)_
3. **Local, on-device personal tuning.** `vanta tune lora` trains a local adapter from the
   operator decisions you've accepted and rejected — on-device (MPS / CUDA / CPU), nothing
   leaves the machine. Hermes also supports tuning (RL via Atropos); Vanta's distinction is
   that it's local-first and driven by _your own_ operator decisions, not a separate
   training pipeline. OpenClaw has no personal tuning.

## Where Hermes and OpenClaw lead today

We'd rather you hear it here than find out later. Vanta still has **core trust
and reliability release work**, in addition to ecosystem and reach gaps:
universal effect mediation, credential isolation, exact approval binding,
untrusted-content quarantine, completion/recovery reconciliation, and the
legacy factory promotion boundary. See [Product acceptance](/acceptance),
[Comms & gateway](/comms-and-gateway), and
[Self-improvement](/self-improvement).

- **Community ecosystem scale.** Vanta now ships a public multi-source skill registry
  client with verified previews, approval-gated install/update, quarantine, and reversible
  removal. Hermes's Skills Hub and OpenClaw's plugin marketplace still lead in public
  catalog size and contributor activity.
- **Proven mobile reach.** Vanta ships a native mobile surface over its API/gateway, and
  its Termux installer passes emulator and CI gates. OpenClaw still leads in mature mobile
  node reach; Vanta's physical ARM64 Termux run remains an external acceptance gate.
- **Community & maturity.** Both have a head start in public users and contributions;
  Vanta is newer.

The current Hermes-main delta also exposed six narrower reliability and routing gaps. Vanta
has shipped durable unknown-effect disposition, real-headroom compaction, route-aware usage,
session-scoped model changes, gateway context references, and bounded authenticated readiness.
All six local delta cards are shipped. See the
[current delta audit](https://github.com/jpoindexter/Vanta/blob/main/docs/research/hermes-current-delta-2026-07-12.md).

## Migrating to Vanta

Importers between these tools are standard in this category — OpenClaw imports from Codex
CLI, Claude, and Hermes; Hermes imports from OpenClaw. Vanta ships the same outcome:
`vanta migrate openclaw|hermes` imports skills, MCP servers, and model config into
`~/.vanta`, with a preview → select → backup → apply flow and secrets redacted in the
report.
